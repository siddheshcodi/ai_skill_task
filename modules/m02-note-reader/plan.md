## 1. Goal

Turn a folder into `(notes, skipped)` with no exception ever escaping. Header parsing must be easy to extend once real note formats are known (Q1).

## 2. Design decisions

| Decision | Choice | Rationale |
|---|---|---|
| File discovery | `sorted(p for p in folder.iterdir() if p.is_file() and p.suffix.lower() == ".md")` | Top level only (QA-4); case-insensitive extension (QA-3); sorted for stable order (TC-RDR-009) |
| Hidden / lock files | Skip names starting with `.` or `~` silently | TC-RDR-008 |
| Decoding | `path.read_bytes()` then `.decode("utf-8-sig")`; on `UnicodeDecodeError`, try a UTF-16 BOM check, else skip | Handles BOM (TC-RDR-063) and Notepad UTF-16 (QA-8) |
| Header patterns | A list of compiled regexes per field (`DATE_PATTERNS`, `ATTENDEE_PATTERNS`), tried in order | New formats from the sample notes are one-line additions |
| Header region | Search the first 30 non-empty lines for the date; first match wins | Avoids `Date:` text in the body (TC-RDR-030); one rule for two `Date:` lines (QA-7) |
| Date parsing | `date.fromisoformat` for ISO; extra formats added only if samples need them | Never guess a wrong date (TC-RDR-024) |
| Attendees | Split on `,`; strip spaces and markdown bold; drop empties; de-duplicate while keeping order | TC-RDR-042, 045 |
| Missing attendees | Allowed (`[]`) | Spec §6 assumption; TC-RDR-048 |
| Error boundary | A `try/except Exception` around each file, giving `SkippedFile(name, "unexpected error: …")` | NFR-01, TC-RDR-092 |

### Header regexes (initial; refine in milestone 1)

```python
DATE_RE      = re.compile(r"^\s*\**date\**\s*:\**\s*(?P<value>.+?)\s*$", re.I)
ATTENDEES_RE = re.compile(r"^\s*\**attendees\**\s*:\**\s*(?P<value>.*?)\s*$", re.I)
TITLE_RE     = re.compile(r"^\s*#\s+(?P<value>.+?)\s*$")
```

### Skip reasons (constants, used by M10 and tests)

`file is empty` · `no meeting date found` · `invalid meeting date '<v>'` · `cannot read file (encoding error)` · `cannot read file (permission denied)` · `unexpected error: <msg>`

## 3. Components

```python
def read_notes(folder: Path) -> tuple[list[Note], list[SkippedFile]]: ...
def list_note_files(folder: Path) -> list[Path]: ...
def read_text(path: Path) -> str: ...                 # raises ReadError(reason)
def parse_note(file_name: str, text: str) -> Note: ... # raises MalformedNote(reason)
def parse_meeting_date(text: str) -> date: ...
def parse_attendees(text: str) -> list[str]: ...
def parse_title(text: str) -> str | None: ...
```

`parse_note` is pure (string in, `Note` out), so most TC-RDR cases run without touching the file system.

## 5. Test approach

- One fixture folder per scenario under `tests/fixtures/reader/`. The bad-encoding and binary fixtures are generated by test setup code, so editors don't "fix" them.
- `parse_note` tests use inline strings with `pytest.mark.parametrize`.
- Fuzz test: 100 random-byte files in `tmp_path`. Assert `len(notes) + len(skipped) == 100`.
- The "never edits notes" check (TC-RDR-093) compares hashes before and after a full ingest.

## 6. Risks

| Risk | Mitigation |
|---|---|
| Real formats differ (Q1) | Milestone 1 happens before coding; pattern lists are easy to extend |
| Ambiguous date formats in headers (`06/10/2026`) | Only enable formats seen in samples; same DD/MM rule as M5 (QA-23) |
